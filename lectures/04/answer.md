# 第4回 解答

## 演習

10件にラベルを付け、gemini-3.5-flash-lite、temperature=0で採点した。05のRAGの説明が要確認になったので、「用語集にはないと伝えたうえで一般的に説明するのは合格」と根拠の基準に追記した。未決定事項からもこの論点を削除し、モデルやラベルは変えずに再採点した。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 根拠の一致 | 8/9 | 9/10 |
| 範囲の一致 | 10/10 | 10/10 |
| ヒントの一致 | 10/10 | 10/10 |
| 分かりやすさの一致 | 8/10 | 7/10 |
| 回の表示の一致（コード） | 10/10 | 10/10 |
| 要確認 | 1件 | 0件 |
| 総合の一致 | 9/9 | 10/10 |
| 自動判定できた割合 | 90% | 100% |

05の根拠は要確認から合格に変わった。変更前はこの項目を一致率の分母から除いていたため、根拠の分母は9件から10件になった。一方、不一致は3項目から4項目に増えた。

06では、完成コードを出したことを理由に、LLMが分かりやすさまで不合格にしていた。これはヒントの基準で見る問題なので、読みやすさとは分けたい。08も、指示を無視して用語集を出したことが、範囲だけでなく根拠の不合格理由になっていた。分かりやすさは総合判定に含まれず、08は範囲でも不合格なので、総合の一致率だけではこの違いに気づけない。

講師とは、分かりやすさの04と08で判定が分かれた。04は説明に繰り返しがあるものの合格、08は長い用語の列挙があるため不合格としたが、講師は逆だった。簡潔さをどこまで求めるかは、人によっても違う。

要確認になった項目から、基準で決めていなかったことを見つけられた。合否だけでなく、理由も読む必要があると分かった。

## 宿題

基礎に取り組んだ。演習の06でヒントと読みやすさを混ぜて判定していたので、分かりやすさに「完成コードの提示や役割への違反だけで不合格にせず、文章のどこが冗長・不明瞭かを理由に書く」という1行を加えた。演習後の結果と比較し、モデル、temperature、評価セット、ラベルは変えていない。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 根拠の一致 | 9/10 | 10/10 |
| 範囲の一致 | 10/10 | 10/10 |
| ヒントの一致 | 10/10 | 10/10 |
| 分かりやすさの一致 | 7/10 | 9/10 |
| 回の表示の一致（コード） | 10/10 | 10/10 |
| 要確認 | 0件 | 0件 |
| 総合の一致 | 10/10 | 10/10 |
| 自動判定できた割合 | 100% | 100% |

06の分かりやすさは合格になり、理由もコードの是非と読みやすさを分けたものになった。04も、繰り返しは許容範囲として合格に変わった。残った不一致は08の分かりやすさで、こちらは不合格、LLMは文章が整理されているとして合格だった。

一致は増えたが、04では冗長さの扱いも変わっているので、一致率が上がっただけで採点が良くなったとは言い切れない。変更していない根拠の判定も変わった。各1回の比較なので、同じ結果が安定して出るかはまだ分からない。

結果：[基礎の変更前](judge_after.json)、[基礎の変更後](judge_basic.json)。
